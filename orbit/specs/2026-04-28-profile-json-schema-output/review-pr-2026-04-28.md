## Findings

### [LOW] #1 — Helper module path deviates from spec (ac-02 + constraint 8)

**Category:** environment-mismatch
**Description:** Spec ac-02 mandates the helper at `crates/finetype-cli/src/json_schema.rs`
("CLI-internal helper module"). Constraint 8 names the same path verbatim. The
implementer placed it at `crates/finetype-mcp/src/json_schema.rs` instead. The
rationale recorded in `progress.md` line 8 is sound: `finetype-cli` already
depends on `finetype-mcp`, so the helper is reachable from both call sites
without violating constraint 8's *spirit* (don't promote to `finetype-core`).

**Evidence:**
- `crates/finetype-mcp/src/json_schema.rs` exists (192 lines).
- `crates/finetype-cli/src/json_schema.rs` does **not** exist.
- `crates/finetype-cli/src/main.rs:8` imports `use finetype_mcp::json_schema;`.
- `progress.md:8` discloses the deviation with rationale.
- spec.yaml ac-02 line 39–49 + constraint #8 line 22 specify the CLI path.

**Recommendation:** Acknowledge as an intentional deviation. The spec's
*goal* — keep the helper out of `finetype-core`, share between CLI and MCP —
is satisfied. The path delta is mechanical and does not affect the public
contract. Card 0006's spec note (constraint 8 second sentence: "Card 0006
extends the same helper for type-mode") still holds, the helper just lives
in a different crate. **Approve as-is**; suggest a one-line addendum in the
spec or a memo recording the path migration so card 0006's review-spec doesn't
flag it as a regression. Either tighten via the spec amendment skill or fold
into card 0006's design discussion.

### [LOW] #2 — ac-10 round-trip (degraded path) collapses to a duplicate of ac-08

**Category:** test-gap
**Description:** Per `progress.md:30-32` the round-trip path took the
documented degradation: structural-shape assertions on parsed JSON in
`golden_profile_json_schema_people_directory`. The review-spec already
flagged this in advance (review-spec finding 3, "silent-pass risk").
Empirical round-trip via temp file shows 113 rejects on
`people_directory.csv` — `salary` values fail the `finance.currency.amount`
regex (data lacks currency prefix), `ssn` values fail the
`identity.government.ssn` regex (mock data has the wrong shape). These are
**type-pattern strictness mismatches against synthetic data**, not
schema-emission bugs. Confirmed by sampling rejects via DuckDB
`finetype_reject_errors` — all rejects are `pattern` failures on values
that genuinely don't match the inferred type's regex.

**Evidence:**
- `./target/debug/finetype profile -f eval/datasets/csv/people_directory.csv -o json-schema | finetype validate` produces 113 rejects, all `constraint_failed: pattern`.
- Top reject: `salary` column, `pattern` constraint, value lacks `$` prefix expected by `finance.currency.amount` regex.
- Spec ac-10 explicitly accepts the degraded path: "OR (degraded) `serde_json::from_str` succeeds and the parsed document satisfies the structural assertions named in ac-08." Implementation honors this.

**Recommendation:** Card 0005's spec must include a "round-trip with
`profile -o json-schema` output as input" AC, ideally on a fixture whose
data values *do* satisfy the inferred type contracts (e.g. a synthesised
fixture per type). Surface in card 0005's `/orb:review-spec`. **No change
required for this PR.**

## Honest Assessment

This PR is implementation-ready. Code quality is high: the helper is
well-documented (module-level docs cover the verbosity contract and
`--stats` semantics explicitly), the CLI/MCP lockstep is clean (both
surfaces route through `emit_table_schema()`), the verbosity contract
from PR #51 is preserved (only `x-finetype-label` + `x-finetype-pii`
appear; the 6 dropped extensions are absent — verified empirically and
in golden negative-assertions), and the clap-based `--stats` conflict
yields a clean exit 2 with the verbatim spec message.

The `OutputFormat::JsonSchema` variant is correctly threaded through
**every** match arm in `main.rs` (`cmd_infer`, `cmd_taxonomy`, `cmd_check`,
`cmd_validate_table`, `cmd_eval`) — no compile errors or silent fall-through.
The non-`profile` paths route to plain-text behaviour, which is the
right default for a format that's table-schema-only.

The MCP `schema` tool's table-mode hard-error is implemented as a `const`
(`TABLE_MODE_MIGRATION`) and reused for both `path` and `data` branches —
no string drift. Rust's line-continuation `\` correctly trims the indentation
so the const is byte-identical to the spec's mandated migration string.

The single notable deviation is the helper module path (Finding #1) —
moved from `finetype-cli` to `finetype-mcp` for legitimate cross-crate
reachability reasons. The spec's spirit (don't promote to `finetype-core`)
is honored. The deviation is logged in `progress.md`. Card 0006 will need
to extend the same helper at the new location; surface this in 0006's
`/orb:design` or `/orb:review-spec` so it's not flagged as drift.

The round-trip (ac-10) takes the documented degraded path because card
0005's stdin support hasn't shipped. This is structurally fine — but the
manual round-trip experiment shows that even *with* stdin support, this
PR's output won't cleanly round-trip on `people_directory.csv` because
the inferred type patterns are stricter than the fixture's actual values.
This is a data-quality problem, not a schema-emission problem, and
belongs to card 0005's responsibility to surface honestly. The
emit-side contract is correctly implemented here.

Net: 11/11 ACs verified, all `make ci` components green, 3/3 new golden
tests pass, no regressions in the 700+ existing tests, no new clippy
warnings in the touched crates. **APPROVE.**
