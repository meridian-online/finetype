## Findings

### [INFO] Three pre-existing golden_profile failures
**Category:** test-gap (pre-existing, not introduced)
**Description:** `golden_profile_ecommerce_orders`, `golden_profile_people_directory`, `golden_profile_titanic` fail on the PR branch.
**Evidence:** Switching to `main` and running `cargo test -p finetype-cli --test cli_golden -- --ignored golden_profile_ecommerce_orders golden_profile_people_directory golden_profile_titanic` produces the identical 3 failures with byte-identical error messages — they're v19-promotion model-classification noise unrelated to this spec, as documented in PR description and `progress.md` Detours.
**Recommendation:** Not a blocker. These should be tracked under the v19 promotion follow-up arc (5 cross-domain regressions noted in `CLAUDE.md`'s "What's next" section).

### [LOW] CLAUDE.md env-var table drift
**Category:** doc-drift
**Description:** `CLAUDE.md:313` still describes `FINETYPE_MODEL` as "Path passed to `finetype --model`" — but `--model` was removed by this PR.
**Evidence:** `grep -n "finetype --model" CLAUDE.md` → line 313.
**Recommendation:** Single-line edit to "Direct env var read by CLI; default `models/default`" or similar. AC-8 requested a "single-pass edit" to refresh changed surfaces — this row was missed. Worth folding into the same merge or the immediate follow-up doc-refresh PR (`CLAUDE.md` doc-refresh is already on the deferred-followups list).

### [LOW] No new `vrp_*` integration tests
**Category:** test-gap
**Description:** Spec verification text on AC-6 and AC-7 explicitly requests new `vrp_*` tests:
- AC-6: "Add a `vrp_*` test that round-trips `finetype schema <csv> | finetype validate <csv> <schema>` and asserts `finetype_reject_errors.type_confidence` is NULL across all rows."
- AC-7: "Add `vrp_*` integration tests covering: check-only mode (plain + json output), check-only + lenient, half-pair rejection (both directions), append-without-db rejection, full-pair behaviour-preservation."
Neither is present in the diff. Coverage is via (a) clap-level errors which the binary exercises at runtime, (b) existing `vrp_*` tests in `crates/finetype-core/src/table_validator.rs` from PR #46 which still pass, (c) updated schema-golden assertions in `cli_golden.rs`. The round-trip behaviour is verified manually in this review (NULL `type_confidence` confirmed against /tmp/out.db) but is not covered by an automated regression test in this PR.
**Evidence:** `git diff main...HEAD -- crates/finetype-cli/tests/ crates/finetype-core/tests/` shows only the schema-golden update; no new `vrp_ac06_*` or `vrp_ac07_*` test fns added.
**Recommendation:** Not a blocker — clap is reliable, the surface change is small, and the round-trip property is captured in MADR 0064 plus the AC-6 CHANGELOG note. Consider adding the round-trip test as a follow-up alongside the doc-refresh PR.

### [LOW] Decision 0064 partial invalidation
**Category:** decision-drift
**Description:** MADR 0064 (`validate-as-duckdb-reject-pipeline.md:78-81`) cites as a "Good" consequence: "authored-time `x-finetype-label` and `x-finetype-confidence` round-trip as `expected_type` and `type_confidence` in the sidecar". AC-6 drops `x-finetype-confidence` from emitted schemas, so the `type_confidence` round-trip property is lost for v0.6.19+ schemas (NULL for new schemas; pre-existing schemas continue to populate it).
**Evidence:** `grep -n "x-finetype-confidence" orbit/decisions/0064-validate-as-duckdb-reject-pipeline.md` returns line 79; AC-6 description acknowledges this in its CHANGELOG note.
**Recommendation:** Not a blocker — the spec is explicit and a CHANGELOG note documents the consequence. Worth a one-paragraph amendment to MADR 0064 (or a new MADR superseding the round-trip claim), to keep the decision register honest about which rationales remain in force. Spec.yaml `decisions_to_record` already plans a separate MADR for "schema verb folds entirely"; this could ride alongside.

## Honest Assessment

This is a clean, surgical surface-cleanup PR. All 10 ACs and 11 hard
constraints from the spec ship as described in `progress.md`. Manual
smoke-tests confirm behaviour for AC-1 through AC-10. The three
pre-existing `golden_profile_*` failures are independently verified to
exist on `main` HEAD with byte-identical error messages and are not
caused by this work. Diff scope discipline is strong — exactly the
surfaces named in the spec, and the dead-code removal of `eval-gittables`
correctly preserves the standalone binary.

The only real findings are low-severity polish: (a) one residual line in
`CLAUDE.md`'s env-var table still references the removed `--model` flag,
(b) the spec asked for new `vrp_*` integration tests for AC-6 and AC-7
that weren't added (existing `vrp_*` tests in core still cover validate's
engine; the new flag-pair semantics rely on clap behaviour, which is
reliable), and (c) MADR 0064's "type_confidence round-trip" rationale is
now partially invalidated by AC-6's confidence-drop and deserves a small
amendment to keep the decision register honest. None of these block
merge — they're follow-up polish that fits naturally into the already-
planned doc-refresh PR.

The hard-removal posture (no deprecation cycle) is appropriate for an
internal-tool CLI and the migration is clean: every removed surface
errors with a clear clap message, every internal caller has been
migrated in the same PR, and the public 7-verb surface aligns with the
v0.6.19 release theme. Recommend approving and merging.
