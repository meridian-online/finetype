## Findings

### [HIGH] AC-06 floor gate failed: 98 prescreen columns at `pass_floors=False`
**Category:** test-gap / spec-violation
**Description:** AC-06's verification block requires `awk -F'\t' 'NR>1 && $14=="False"' /tmp/validate_corpus_iter2_prescreen.tsv | wc -l` to return 0. Actual count is 98 across 10 of the 12 datasets (5 iter-1 + 5 iter-2). The progress.md self-reports the deferral with reasoning ("floors calibrated for synthetic training data, not real-world heterogeneity"), but the deferral is not documented in the iter-2 report at `eval/eval_output/validate_corpus.md` as the progress note implies. `grep -E "prescreen|floors|MADR 0055" eval/eval_output/validate_corpus.md` returns no matches.
**Evidence:**
```
$ python3 scripts/prescreen_eval.py --manifest /tmp/validate_corpus_iter2_prescreen.csv --output /tmp/validate_corpus_iter2_prescreen.tsv
prescreen: 168 pass / 98 fail / 0 error (of 266 manifest rows)
$ awk -F'\t' 'NR>1 && $14=="False"' /tmp/validate_corpus_iter2_prescreen.tsv | wc -l
98
$ awk -F'\t' 'NR>1 && $14=="False" {print $1}' /tmp/validate_corpus_iter2_prescreen.tsv | sort | uniq -c
   5 co2_emissions_by_nation
   9 fifa_players
  33 gdelt_events
   1 global_temp_annual
  11 nyc_taxi
  24 oecd_employment
   2 pokemon
   5 rio2016_athletes
   7 un_locode
   1 us_baby_names
```
The iter-1 datasets (pokemon, rio2016_athletes, etc.) also fail floors today — this is not strictly an iter-2 regression but the spec demanded the gate pass for all new datasets, and the iter-2 datasets contribute 77/98 of the failures.

**Recommendation:** Pick one of the following before merge:
1. **Loosen the floors** in `eval/pre-screen_floors.yaml` to admit real-world data heterogeneity (the legitimate concern raised in progress.md), update MADR 0055 to acknowledge real-vs-synthetic split, and re-run the gate with 0 fails. This is the principled fix.
2. **Document the deferral in the iter-2 report itself** (not just progress.md) — append a section explaining why prescreen is deferred for the validate-corpus, file a follow-up card to recalibrate floors, and update AC-06's status in the spec to reflect the gap-downgrade (parallel to AC-08's constraint #10 path). This is the pragmatic fix.
3. **Drop or replace the 5 iter-2 datasets that fail floors** (gdelt, nyc_taxi, oecd, fifa, sp500 all have ≥1 fail). This is faithful to the spec but contradicts the curation thesis and would re-open the source-pick effort.

The current state is "spec said gate must pass; gate doesn't pass; deferral is asserted in progress.md only" — that's a process gap.

### [LOW] AC-05 firewall test only has 3 PASS assertions, spec implied ≥8
**Category:** test-gap
**Description:** AC-05's verification block says: "Expected post-state: ≥8 PASS assertions (3 iter-1 + 5 iter-2)." The committed test at `scripts/eval_leakage/test_validate_corpus_firewall.py` runs 3 PASS assertions total (dry-run-reads-both, no-validate-skips, fixture-hash-deterministic). It does not iterate over each new dataset to assert ≥1 PASS per new dataset, so a silent skip of any iter-2 dataset would surface only as a line-count delta that's still "strictly greater than" the eval-only count.
**Evidence:**
```
$ python3 scripts/eval_leakage/test_validate_corpus_firewall.py 2>&1 | grep -c "PASS:"
3
```
The script's third assertion does check that adding the validate manifest grew the hash set (237860 → 351503, a 113k-row delta), which is a strong floor — but it's a single assertion, not 8.

**Recommendation:** Either (a) extend the test to iterate the 5 new datasets and assert each contributes ≥1 hash to the post-state set, or (b) tighten the spec's verification block in a follow-up to match the as-built test design (3 robust assertions covering dry-run, eval-only, and full-run-grows-set). The current behaviour is functionally correct; only the AC verification text is over-specified relative to the implementation.
