## Findings

### [LOW] test_prefix declared but unused
**Category:** test-gap
**Description:** `metadata.test_prefix: svf` in spec.yaml is not applied to any test names. The codebase does not use numeric AC prefix conventions; verifications instead name specific test functions or shell checks. This is consistent with how card 0003 (PR #53) shipped — same prefix gap, same project convention.
**Evidence:** `Grep "svf_ac\d+|fn svf"` returns no files.
**Recommendation:** Future spec generators could either (a) drop `test_prefix` for repos that don't use prefix conventions, or (b) project-wide adopt prefix-tagged test names. **Not a blocker for this PR** — every AC's verification text is independently satisfied.

### [LOW] ac-02 verification text uses `email` shorthand
**Category:** spec-precision
**Description:** ac-02's verification line says `cargo run -p finetype-cli -- taxonomy email` succeeds. In practice the bare token `email` is not an exact taxonomy key — only `identity.person.email` is. The implementation correctly mirrors the original `cmd_schema` behaviour (exact key OR glob) and rejects the bare token with edit-distance suggestions. Verified: `./target/debug/finetype taxonomy identity.person.email -o json-schema` succeeds with the expected single-element array.
**Evidence:** `git show main:crates/finetype-cli/src/main.rs` confirms the original `cmd_schema` had identical exact-match semantics — the bare `email` would have errored on main too.
**Recommendation:** Spec verification text should have read `taxonomy identity.person.email`. **Not a behaviour bug** — the implementation matches the AC description ("exact key OR `prefix.*` / `prefix*` glob") and preserves byte-for-byte parity with the v0.6.18 verb. Treat the verification gloss as a casual shorthand.

### [INFO] One descriptive `cmd_schema` reference remains as a comment
**Category:** cosmetic
**Description:** main.rs:2391 contains a comment "`cmd_schema` (card 0006 absorbs that path)" that explains the historical lineage of the predicate logic now living in `cmd_taxonomy`. The strict grep in ac-04's verification still returns no function-name hits — only this descriptive comment.
**Evidence:** `grep -nE "Commands::Schema\|fn cmd_schema\b\|fn cmd_schema_table\|fn build_json_schema"` returns no hits (function-boundary regex used in spec). A looser grep returns the comment.
**Recommendation:** None — comment is explanatory and aids future archaeology. The spec's verification regex was function-boundary-anchored (`fn cmd_schema\b`) and is satisfied.
