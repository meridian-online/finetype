The committed file has 44 rows (18 fixes + 18 label-change-same-correctness + 8 regressions) — a flipped-rows-only view, not a full per-column view. The verdict math (+10) is internally consistent, but the artefact does not match the spec's structural contract and cannot be used to verify coverage.

Two smaller deviations:

- ac-08 required a v19 smoke model at `models/sherlock-v19-smoke-seed-42/` with 5 files. The directory does not exist. The detour in progress.md justifies this ("informationally null because the mechanism is pipeline-only") and the justification is defensible, but the detour modifies the spec contract without a corresponding spec version bump; v1.2's ac-08 text still explicitly requires the model directory.

The PR's technical substance is strong and the fix should ship. The request is to either (a) rename verdict files / regenerate the per-column full-eval artefact / add the `amvg` tests to match the spec, or (b) bump the spec to v1.3 with an explicit detour clause codifying what actually shipped.

## Findings

### [HIGH] Spec-cited `amvg` tests do not exist
**Category:** test-gap
**Description:** Spec v1.2 cites nine named tests (`test_amvg_ac01_corpus_counts`, `..ac02_jaccard`, `..ac03_confusion`, `..ac04_confidence`, `..ac05_madr_contract`, `..ac07_mechanism_reduced`, `..ac08_smoke_run`, `..ac09_unblock_gate`, `..ac10_regression_guard`) that enforce artefact shape, value ranges, softmax-sanity, MADR frontmatter contract, verdict/net-lift consistency, and regression-guard consistency. None are present in the workspace.
**Evidence:**
```
$ grep -rn "test_amvg" /Users/hugh/github/meridian-online/finetype/ 2>/dev/null
(no matches)
$ cargo test --workspace -- --list 2>&1 | grep -c amvg
0
```
The implementer's workflow relied on one-shot scripts (`scripts/amvg/ac0[1-8]_*.py`) that produce TSVs; the TSVs are manually inspected. There is no CI guard against regeneration producing malformed outputs, no guard against ac-09/ac-10 verdict files disagreeing with their own numeric payload, no guard that softmax rows sum to (0, 1].
**Recommendation:** Add `test_amvg_ac*` tests — minimally ac-09 and ac-10 verdict-vs-numerics consistency tests (read the verdict file, compute net_lift / regression_delta from the TSV, assert both match). These are the two gate ACs; skipping tests there is the highest-regret omission. ac-01..04 structural assertions (row counts, value ranges) are next-priority. If the decision is to ship without tests, bump the spec to v1.3 and delete the "Test test_amvg_..." verification clauses explicitly.

### [HIGH] Verdict files violate the "exactly `GO`/`NO-GO`/`PASS`/`FAIL`" contract
**Category:** bug
**Description:** Spec ac-09 verification: "verdict file contains exactly `GO` or `NO-GO`". Spec ac-09 description: "recorded to diagnostics/v19_smoke_verdict.txt as exactly `GO` or `NO-GO` (no whitespace, no trailing newline)". Spec ac-10 parallels for `PASS`/`FAIL`.
**Evidence:**
```
$ wc -l diagnostics/v19_smoke_verdict.txt diagnostics/v19_smoke_regression_verdict.txt
       8 diagnostics/v19_smoke_verdict.txt
       7 diagnostics/v19_smoke_regression_verdict.txt
```
Both files are multi-line structured-log formats (`verdict: GO\ntarget_columns: 11\n...`). The expanded format is informative, but it does not satisfy the spec contract. Any `test_amvg_ac09_unblock_gate` following the spec verification text would fail on the first read.
**Recommendation:** Either (a) split into two files per gate — `v19_smoke_verdict.txt` containing exactly `GO` (no whitespace, no newline) and a companion `v19_smoke_verdict.meta.tsv` for the structured payload; or (b) update the spec to v1.3 declaring the structured YAML-ish format as the new contract. Option (a) preserves the machine-parseable invariant that enables `/orb:drive`-style gates elsewhere.

### [HIGH] `full_eval_delta.tsv` shape divergence from spec ac-08
**Category:** bug
**Description:** Spec ac-08 verification: "Full-eval delta artefact at diagnostics/v19_smoke_full_eval.tsv with one row per non-target eval column (341 rows), columns = {eval_column, v16_correct, v19_correct, delta}". The committed artefact is `full_eval_delta.tsv` (different filename) and contains 44 rows (18 FIX + 18 LABEL_CHANGE_SAME_CORRECTNESS + 8 REGRESS), columns = {dataset, column, expected, pre_pred, post_pred, pre_ok, post_ok, delta} (different schema — 8 cols vs 4). The regression verdict file reports `non_target_columns_compared: 437` (not 341, and not 44).
**Evidence:**
```
$ wc -l diagnostics/full_eval_delta.tsv
      45 diagnostics/full_eval_delta.tsv   # 44 data rows + 1 header
$ awk -F'\t' 'NR>1{print $8}' diagnostics/full_eval_delta.tsv | sort | uniq -c
  18 FIX
  18 LABEL_CHANGE_SAME_CORRECTNESS
   8 REGRESS
```
The spec asked for a dense table (one row per column, including no-change rows) so that a `test_amvg_ac08_smoke_run` could assert row count == 341 as a coverage check. The sparse committed file cannot support that assertion and diverges from the spec's structural contract. The numeric verdict (+10) is internally self-consistent (18 - 8 = 10) but the column-count bookkeeping is opaque (437 in the verdict vs 341 in the spec vs 44 in the file — three different numbers).
**Recommendation:** Regenerate `full_eval_delta.tsv` with one row per non-target column (441 non-target eval columns per constraint 10; 437 / 341 / 341 discrepancies need a single canonical number). Alternatively, bump the spec to v1.3 with an explicit clause declaring "sparse flipped-rows-only" as the new contract and resolving the 437/341 discrepancy in prose.

## Honest Assessment

The substantive engineering is excellent. The diagnostic arc is reproducible, the mechanism is rigorously ruled-in (and the four alternatives rigorously ruled out with evidence citations in MADR 0065), the fix is surgical (12 match arms in one file, no retrain, no data changes), and the full-eval deltas exceed both gates by wide margins (+11 target vs threshold +3; +10 non-target vs threshold -1). MADRs 0065/0066/0067 form a coherent trio that updates the sprint policy honestly. Tests and taxonomy checks pass. This PR should merge.

The review-blocking concerns are entirely about spec-vs-deliverable traceability, not substance: nine spec-cited tests are missing, two verdict files violate their own format contract, one artefact (`full_eval_delta.tsv`) has a shape that cannot support the spec's row-count assertion, the v19 smoke model directory is absent per a defensible but undocumented detour, and `cargo fmt --check` fails on the two new examples. Every one of these is mechanical to fix. The choice is between a cheap spec-bump-to-v1.3 that codifies what actually shipped, or a slightly more expensive pass that adds tests, renames files, and regenerates the dense non-target TSV. Either path resolves the contract violations and lets this PR ship cleanly.
