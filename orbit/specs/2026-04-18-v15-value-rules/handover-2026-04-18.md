## Recommendation: revise v15 approach before implementing

The header hint impact analysis changes the picture. The current v15 spec adds 6 rules to compensate for header hints overriding correct model predictions. But the analysis shows a simpler path:

### Proposed v15 approach (hybrid, Option C from analysis)

**Step 1: Selective hint removal (subtractive — less code)**
Remove or narrow 4 specific keyword matches that cause the most harm:
- `h.contains("email")` → change to exact match `h == "email"` (stops matching "email_display")
- `h.contains("phone")` → change to exact match `h == "phone"` (stops matching "phone_e164")
- Review which hint is pushing sha256→tsid, gap→amount_accounting, depthError→latitude
- This alone could fix 6+ columns with no new rules

**Step 2: Value-based rules only where needed (2 rules, not 6)**
- R25: status_code → integer_number (model doesn't get this right without hints either)
- R27: year → compact_ym (model doesn't get this right without hints either)
- R26 (hash), R28 (email_display), R29 (phone_e164), R30 (gap/decimal) may become unnecessary after Step 1

**Step 3: Re-eval and assess**
Run full eval after Steps 1–2. The target 223/227 may be achievable with less code than the current spec.

### Why this is better

- Removes root causes instead of adding compensating code
- Aligns with decision 0042 (remove regex header hints)
- Net code deletion, not addition
- The 4 bonus columns from the analysis (depthError, user_agent, mdy_dash, response_time_ms) come free
