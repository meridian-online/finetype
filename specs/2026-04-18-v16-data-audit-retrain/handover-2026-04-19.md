## Critical Discovery: Sweep Tested v14, Not v16

The 3-seed sweep (42, 43, 44) reported 233/242 for all seeds. **These scores are v14, not v16.**

**Root cause:** `scripts/sweep_v16.sh` sets `FINETYPE_MODEL_DIR` env var for eval, but the CLI ignores this. The CLI's `--model` flag defaults to `models/default` (a relative path), which pointed to `sherlock-v14` throughout the sweep. The `FINETYPE_MODEL_DIR` env var is only used by the DuckDB extension, not the CLI.

**Real scores on corrected eval (242 columns):**
- v14: **233/242** (96.3%)
- v16 (seed 42, promoted): **226/242** (93.4%) -- REGRESSION

## Why v16 Regressed

`_DROP_ALL_TYPES` in `scripts/prepare_multibranch_data.py` drops types from BOTH distilled AND synthetic data, giving them zero training examples:

```python
_DROP_ALL_TYPES = {
    "identity.government.ssn",           # v13
    "technology.internet.user_agent",     # v13
    "finance.banking.swift_bic",         # v16
    "technology.internet.http_method",    # v16
    "representation.file.excel_format",  # v16
    "identity.medical.loinc",            # v16
    "identity.medical.cpt",             # v16
}
```

**6 of 16 v16 errors are self-inflicted** from dropping types:
- ssn: 2 columns (people_directory, new_identity)
- http_method: 2 columns (network_logs, server_logs_json)
- cpt: 1 column (new_identity)
- loinc: 1 column (new_identity)

The distilled data for these types IS garbage (that's why they were dropped). But the synthetic generators are fine. Zero training data = model can't predict the type at all.

## What Needs to Happen

**Option 1 (approved by Hugh):** Split `_DROP_ALL_TYPES` into two sets:

1. `_DROP_DISTILLED` = all 7 types (bad distilled data, drop from distilled only)
2. `_DROP_SYNTHETIC` = empty set initially (all generators produce valid data)

This keeps synthetic training data for ssn, http_method, cpt, loinc, etc. while still filtering out the garbage distilled rows.

### Implementation steps:

1. **Fix `scripts/prepare_multibranch_data.py`:**
   - Rename `_DROP_ALL_TYPES` to `_DROP_DISTILLED_TYPES`
   - The distilled data filtering already uses this set -- keep that
   - Remove the synthetic data filtering block (lines that delete `_DROP_ALL_TYPES` keys from `synthetic` dict)
   - Or add a separate `_DROP_SYNTHETIC_TYPES = set()` and filter synthetic against that instead

2. **Fix `scripts/sweep_v16.sh` eval:**
   - The eval must use the per-seed model, not `models/default`
   - Either: pass `--model $MODEL_DIR` to the CLI via env var that `profile_eval.sh` respects
   - Or: set `FINETYPE_MODEL` env var (this IS respected by `eval/profile_eval.sh` line 107-108)
   - Fix: change `FINETYPE_MODEL_DIR="$MODEL_DIR"` to `FINETYPE_MODEL="$MODEL_DIR"` in sweep script

3. **Re-run sweep** with seeds 42, 43, 44

4. **Verify** the real v16 score beats v14's 233/242
