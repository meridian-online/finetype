## Findings

### [WARN] No round-trip test for hierarchical head
**Category:** test-gap
**Description:** No automated test that trains a hierarchical model, saves it, loads it
via `MultiBranchClassifier::load()`, and runs inference. The VARBUILDER_PREFIX constant
prevents future drift, but there's no proof-by-execution in CI.
**Recommendation:** Add in a future PR. The constant makes this low-risk.

### [WARN] --flat-only still evals pre-existing hier model (FIXED)
**Category:** edge-case
**Description:** The eval loop iterated over both model dirs regardless of `--flat-only`.
Pre-existing `models/sherlock-v2-hier` would trigger a spurious eval attempt.
**Recommendation:** Fixed — eval and summary loops now scoped to `MODELS_TO_EVAL` array.

### [WARN] Spec's epoch-1 timing check not implemented
**Category:** spec-gap
**Description:** Spec OV2-4 requires an epoch-1 timing check (>10min → reduce epochs).
Not implemented. Early stopping (patience) provides a weaker version of this guard.
**Recommendation:** Acceptable deviation — document in findings.

### [INFO] Sherlock model dirs missing config.json/label_map.json
**Category:** environment-mismatch
**Description:** Local model dirs from prior training runs lack required metadata files.
The overnight script, when run, produces complete artifacts.
**Recommendation:** No action — these are local state, not committed.

### [INFO] LogRenderer lifecycle methods are no-ops
**Category:** performance
**Description:** `on_train_start`, `on_train_end`, `on_epoch_end` in LogRenderer delegate
to tracing, which is already called by `train_multi_branch`. Intentional design.
**Recommendation:** No action.

## Honest Assessment

The implementation is correct. The VarBuilder prefix fix is properly aligned between
training and inference via a shared constant. All tests pass, the build is clean. The
overnight script has a minor scoping bug with `--flat-only` (now fixed). The epoch-1
timing guard is missing but early stopping provides adequate protection. Confidence:
high for correctness, moderate for operational edge cases.
