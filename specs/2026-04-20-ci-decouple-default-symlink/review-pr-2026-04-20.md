## Findings

### LOW — Trailing slash in `FINETYPE_CI_MODEL` not normalized
**Category:** assumption
**Description:** If `FINETYPE_CI_MODEL` is set to `sherlock-v16/` (trailing slash), the resolution block accepts it verbatim. Downstream, `curl` would hit URLs like `https://huggingface.co/.../resolve/main/sherlock-v16//model.safetensors` (double slash) and `mkdir -p models/sherlock-v16/` succeeds but downstream path concatenation may yield `models/sherlock-v16//model.safetensors`. HuggingFace's CDN typically normalizes double slashes in paths, and `mkdir -p` / file writes on POSIX also tolerate `foo//bar`. The whitespace trim strips leading/trailing spaces but not `/`. In practice this is unlikely — values come from a hand-edited workflow file — but if someone copies a directory listing with a trailing `/` the script won't warn.
**Evidence:** `.github/scripts/download-model.sh` lines 19-31; reproduced in temp dir — `FINETYPE_CI_MODEL="sherlock-v16/"` produces `Active model: sherlock-v16/` with no error.
**Recommendation:** Optional — add `sed 's:/*$::'` after the whitespace trim to strip trailing slashes. Not a blocker; the workflow file is a controlled-input surface. Flag only.

### LOW — URL interpolation of env var value trusts it implicitly
**Category:** assumption
**Description:** The env var value is interpolated into `${REPO}/${MODEL_DIR}/...` URLs and used as an argument to `mkdir -p`, `curl -sfLO`, and `find`. Because the value is quoted (e.g., `mkdir -p "models/${MODEL_DIR}"`) and no `eval`/`source`/unquoted command substitution is involved, shell-injection via the env var value is not possible. The value is only read by this single script. I confirmed this by running with `FINETYPE_CI_MODEL='; echo HACKED'` — it produced `Active model: ; echo HACKED` with no side-effect execution, just a malformed URL that curl would 404 against. This is safe but worth noting that the trust boundary is "whoever can edit `.github/workflows/*.yml`" — which is already the trust boundary of CI itself. Not actionable.
**Evidence:** `.github/scripts/download-model.sh` lines 34, 38-49; empirical test above.
**Recommendation:** None. Documenting as a closed concern.

## Edge case probing results

```
| Probe                                                    | Result                                                      |
|----------------------------------------------------------|-------------------------------------------------------------|
| Env var unset + models/default as symlink                | Falls through to readlink → resolves to symlink target      |
| Env var unset + models/default as plain-text file        | readlink fails → cat succeeds → resolves to file contents   |
| Env var unset + no models/default                        | Exits 1 with "cannot resolve model" to stderr               |
| Env var = "   " (whitespace only)                        | Stripped to empty → exits 1 with loud error                 |
| Env var = "sherlock-v16\r\n" (Windows CRLF)              | `tr -d '\r'` strips CR → resolves to "sherlock-v16"         |
| Env var = "; echo HACKED" (shell metachars)              | Treated as literal string; no injection — quoted expansion  |
| Env var = "sherlock-v16/" (trailing slash)               | Accepted verbatim; may yield double-slash URL (see finding) |
| Broken symlink (target doesn't exist)                    | Drift check reads link text OK; download-model would 404    |
|                                                          | at curl — loud failure, acceptable                          |
| Resolution block run twice in same workdir               | Idempotent — both invocations resolve identically           |
| `set -euo pipefail` + failing readlink/cat chain         | `|| true` at end absorbs errors; empty-check triggers loud  |
|                                                          | exit instead of silent malformed curl                       |
```

No edge case produces silent malformed behaviour. The `|| true` on line 22 is intentional — it prevents `set -e` from aborting when both `readlink` and `cat` fail, so the explicit empty-check at line 27 can produce the clean error message.

## Honest Assessment

This is a small, well-executed change. The implementation directly mirrors the spec v1.1 — the six Rust/YAML/shell changes are surgical (resolution block, two workflow-level env keys, two new scripts, CLAUDE.md section, handover back-ref), and the two new scripts are tight (32 and 129 lines respectively). All 7 ACs have identifiable coverage, all 7 prior-review findings landed, all 4 test cases pass locally and in CI, and the drift check behaves sensibly across the five scenarios I probed (aligned, divergent, unset, missing symlink, broken symlink).

The only things I found worth flagging are low-severity: trailing slash in the env var is not normalized (would produce double-slash URLs; unlikely in practice), and the trust boundary for the env var value is workflow-file-edit access (already the CI trust boundary). Neither blocks merge. The shell semantics under `set -euo pipefail` are handled correctly — the `:-` form, the `|| true` on the readlink/cat chain, and the explicit empty-check after the whitespace trim together guarantee that no malformed URL reaches curl. The test harness's extraction-by-awk approach is unusual but appropriate here: it exercises the real script text without stubbing curl, which would have been the other reasonable option.

The CI run on the PR (24644654177) shows all 7 jobs green, including the two new `download-model-test` and `drift-check` jobs. Mergeable per gh.

**Verdict: APPROVE.** I couldn't find problems that warrant changes.
