## Findings

### [CRITICAL] CI download script not updated for multi-branch model

**Category:** environment-mismatch
**Description:** `.github/scripts/download-model.sh` still downloads from `meridian-online/finetype-char-cnn` and expects filenames `model.safetensors`, `labels.json`, `config.yaml`. The active model (`models/default → sherlock-v4-sibling`) requires `model.safetensors`, `label_map.json`, `config.json`. The old repo returns HTTP 404 for `sherlock-v4-sibling/*`. With `set -euo pipefail`, CI fails immediately.
**Evidence:**
```
curl -s --head "https://huggingface.co/meridian-online/finetype-char-cnn/resolve/main/sherlock-v4-sibling/model.safetensors"
HTTP/2 404
```
**Recommendation:** Update `.github/scripts/download-model.sh` to download from `meridian-online/finetype-model` and request files `model.safetensors`, `label_map.json`, `config.json`.

### [CRITICAL] HuggingFace model repo not published — DuckDB extension will panic

**Category:** environment-mismatch
**Description:** `meridian-online/finetype-model` on HuggingFace returns HTTP 401 (private or does not exist). The DuckDB extension's `resolve_model_dir()` will fail at runtime. `get_column_classifier()` calls `.expect("Failed to resolve FineType model directory")` — this will panic DuckDB on first `SELECT finetype(...)`.
**Evidence:**
```
curl -s "https://huggingface.co/api/models/meridian-online/finetype-model"
{"error":"Invalid username or password."}
```
**Recommendation:** Publish `sherlock-v4-sibling` model artifacts to HuggingFace as `meridian-online/finetype-model` before merging.

### [WARN] Sharpen pipeline ordering reversed from spec

**Category:** bug
**Description:** Implementation runs value_sharpen → feature_sharpen (column.rs lines 2002–2015). Spec AC-1 specifies feature_sharpen → value_sharpen. Creates potential interaction risk where value_sharpen changes the label, then feature_sharpen operates on the changed label (e.g., R12 promotes/demotes, then F1/F5 fight over the result).
**Evidence:** `column.rs` Step 3 = `value_sharpen`, Step 4 = `feature_sharpen`. Spec AC-1: `(b) feature_sharpen → (c) value_sharpen`.
**Recommendation:** Either swap the order to match the spec, or update the spec and add a comment explaining why.

### [WARN] Missing spec-required tests for AC-2 and AC-3

**Category:** test-gap
**Description:** AC-2 requires tests that F2 fires without docker_ref in votes. AC-3 requires sharpen_attractor_demotion tests (confidence=0.95 no demotion, confidence=0.3 demotes). No new test functions added in this PR.
**Evidence:** `git diff main...HEAD -- crates/finetype-model/src/column.rs | grep "^+.*fn test_"` — empty output.
**Recommendation:** Add the tests specified in AC-2 and AC-3 verification sections.

## Honest Assessment

The core implementation is solid. The Sharpen layer (feature_sharpen, value_sharpen, apply_header_sharpen) is correctly wired into both classify_multi_branch paths, the logic is sound, and the 155/190 eval score is confirmed by a live run. AC-1 through AC-9 are substantively complete.

The two CRITICAL blockers are both in the infrastructure layer, not the inference code: the CI download script will fail on the first run because `sherlock-v4-sibling` doesn't exist on `finetype-char-cnn`, and the DuckDB extension will panic on first use because the model hasn't been published to HuggingFace yet. Both are fixable in under an hour (update the download script, publish the model), but they must be done before merge.
