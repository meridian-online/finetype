## Findings

### [MED-1] Sentinel arithmetic `pre - overlap != post` by 1,240 rows
**Category:** spec-conformance
**Description:** Spec ac-04 states `pre_filter_rows - row_hash_overlap = post_filter_rows` "must hold — any other arithmetic indicates the filter did not run." Observed values give a residual of 1,240 rows: `28,768,204 − 761,219 = 28,006,985` vs logged `post_filter_rows = 28,005,745`.
**Evidence:** `results/sweep-v18.log`:
```
pre_filter_rows: 28768204
row_hash_overlap: 761219
post_filter_rows: 28005745
```
Residual = 1,240 rows.
**Mitigating evidence:** (a) `leaked_rows_after_filter: 0` demonstrates the
firewall re-hash found no eval rows post-filter — the defence-in-depth
check is clean. (b) `progress.md:32` attributes the 1,240-row delta to
"internal-corpus dedup" happening inside `filter_eval_leakage` (the filter
drops columns that fall below `min_values` after eval-row removal, not
just eval rows). This is consistent with the prep-script diff: the
`post_filter_rows` computation sums remaining rows across remaining
columns, whereas `row_hash_overlap` counts only removed rows matching the
eval hash table. (c) `hash_filter_active: true` is emitted only on the
live-filter branch (prep script line ~2949), so the marker's presence
does guarantee the filter ran.
**Recommendation:** Non-blocking for this PR because the defence-in-depth
`leaked_rows_after_filter: 0` satisfies ac-04's underlying intent (prove
the firewall ran, not arithmetically no-op). However, a follow-up card
should tighten ac-04's arithmetic to account for column-pruning side
effects, OR emit a separate marker (e.g., `columns_pruned_by_min_values`)
to close the reconciliation. Flag for v19 spec-writing, not v18 merge.

### [LOW-1] `eval/report.md` literal string match — "Profile" vs "profile"
**Category:** spec-conformance
**Description:** ac-05's verification says each per-seed `eval/report.md`
must contain "the literal string `profile`". The reports contain
"Profile" (capital P) in header cells like "Profile label accuracy" and
"## Profile Evaluation". A strict `grep -c profile` returns 0, but
`grep -ci profile` returns 4+ per file.
**Evidence:** `models/sherlock-v18-seed-42/eval/report.md:9` → `| Profile label accuracy | 297/352 (84.4%) | 🟡 |`
**Recommendation:** Cosmetic. The reports clearly originated from the
profile eval harness (content includes "Profile label accuracy",
"Profile domain accuracy", "Profile regression"). Treat as pedantic
match and accept. Tighten future specs to say "case-insensitive match on
`profile`".

**Category:** environment / release discipline
**Description:** `models/sherlock-v18-seed-{42,43,44}/` and

**Evidence:** `git check-ignore -v` confirms both patterns match project

**Recommendation:** None. Documenting for reviewer trail.

## Honest Assessment

This is a well-instrumented, well-evidenced paper PR. Every claim in
`progress.md` and `handover.md` is backed by an on-disk artefact or a
committed document. The two findings are both minor: MED-1 is a spec-text

discipline) is the most durable win in this spec; it cleans up a signal-
conflation problem that had been silently degrading every prior sweep's
training-variance measurement. The three follow-up generator cards
(amount-variant, container-type, datetime-subtype) are well-scoped
consequences of the triage work. Merge as-is; file MED-1 as a v19
spec-tightening card.
