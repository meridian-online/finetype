## Headline

The gold anchor does the one thing it exists to do: it lets us score a model against labels neither lens produced. The load-bearing property — independence — holds under scrutiny, and the proof is in the v19 baseline itself. A labeller that secretly copied the Sense or YDF prediction would score ~1.0 across every family. Instead v19 lands at 0.167 on Family A and 0.333 integer-recall on Family D against this set. Honest low numbers are the strongest evidence the labels are not a disguised copy of the prediction.

## Independence — scrutinised hardest (the spec's load-bearing property)

This is where a fixture like this fails silently, so I checked it three ways:

1. **No labeller reads the prediction as the label.** Read all four labelling functions in `curate_gold_anchor.py`. `label_family_a/b/d` take only `(header, vals)` — they never receive `ydf`/`sense`. `label_family_c` receives `sense` but uses it solely as a *gate to discover* mis-sensed coordinate candidates, then assigns `decimal_number` by header inspection (`HDR_NONGEO_NUMERIC`), not by echoing `sense`. The `ydf`/`sense` columns in the fixture are retained as `*_context` only — exactly the "discovery, not labelling" use the README permits.

2. **The fixture proves active disagreement, not coincidence.** Family C's 30 `decimal_number` rows are all cases where `sense_context == latitude` but the gold label is `decimal_number` (verified by tabulating curated-vs-sense). If the labeller copied Sense, these would be `latitude`. The override is the proof. (The 165 rows where `curated == sense_context` are coincidental agreement — Sense correctly calling a real longitude `longitude` — not derivation; the labeller arrived there independently via header+range.)

3. **Family B disambiguates by VALUE-LENGTH + header, not ISO vocabulary.** `label_family_b` keys on `RE_2LETTER`/`RE_3LETTER` (shape) plus `HDR_COUNTRY`/`HDR_TEAM_EXCH` (header semantics). There is no membership test against an ISO 3166 alpha-2 set, so it is not a disguised B2 sieve. This is precisely the breach the spec warned against, and it is avoided.

Independence holds.

## Non-blocking findings

1. **Stale module docstring in `scripts/score_gold_anchor.py:9`.** The top docstring still says predict "runs `finetype infer --mode column` (uses models/default)", which contradicts both the implementation (`_profile_column` uses `profile -f csv -o json-schema`) and line 61, which explicitly rejects `infer --mode column`. The code is correct; only line 9 is stale. Worth a one-line fix to avoid future confusion. Not blocking — the harness does the right thing.

2. **The README's hand-curation fallback is described but never exercised.** README §"What 'shares no inputs' means" and families.md line 47-49 say columns needing a full vocabulary lookup are "curated by hand instead" with `labeller: human`. In the actual fixture, all 240 rows carry an auto labeller (`label_a/b/c/d`); zero are `labeller: human`. This is fine — the length+header heuristic was sufficient for the candidates found, so the fallback simply wasn't needed — but the contract documents a path the fixture doesn't demonstrate. If a future curator adds a hard-vocabulary column, that path will get its first real exercise. No action required now.

3. **Family B/D oracle is heuristic, not exhaustive ground truth.** A 2-letter geographic-headed column is labelled `country_code` on shape alone (no value-validity check), and a 4-digit temporal-headed in-range column is `year`. These are deliberate, contract-sanctioned choices (value-length over vocabulary, to stay independent), and the per-row provenance makes each one auditable. The cost is that a 2-letter geographic column whose values are *not* valid ISO codes would still be labelled `country_code`. Acceptable for a tie-breaker oracle and explicitly chosen over the independence-breaching alternative — noted for transparency, not as a defect.
