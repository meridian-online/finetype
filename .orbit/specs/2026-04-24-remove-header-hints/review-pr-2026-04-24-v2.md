## Findings

### [LOW] ac-07 v19-retrain gate widened beyond spec literal
**Category:** spec-deviation (documented and arguably necessary)
**Description:** Spec ac-07 verification reads: "Every family with `domain=='finance'` and `classification=='model-gap'` AND `type_targets` containing `'amount_'` has `blocked_on=='v19-retrain'`." The shipped implementation widens the rule from `domain=='finance'` to `any('finance.currency.amount_' in type_targets)` so cross-domain `header_hint_table` (whose amount-variant arms are the actual MADR 0065 blocker) routes to v19-retrain rather than to a generic `training-data-fortification-…` ticket.
**Evidence:** `progress.md` line 27 documents the widening; `rhh_roadmap.tsv` row 11 shows `header_hint_table` (domain=cross-domain) → `blocked_on=v19-retrain`. The literal spec verification is vacuously satisfied (no row has domain=finance + amount_), so this is not a verification failure — it is a code-side widening that produces a more semantically correct routing.
**Recommendation:** Non-blocking. The widening aligns with MADR 0065 and is documented in the script docstring + progress.md. Consider noting the deviation explicitly in the ac-07 verification text in a future spec amendment.

### [LOW] ac-06 has no dedicated rhh_ac06_* test
**Category:** test-gap (spec-permitted)
**Description:** Spec ac-06 verification is structural ("Row count = 8", "Sum…equals total family count", "Every removal_readiness ∈ {READY, NEEDS_FORTIFICATION, NO_EVIDENCE}"). No `rhh_ac06_*` test is registered in `test_rhh.py`. The invariants are enforced by the ac06 generator's own code path and indirectly via ac-05's arithmetic test, which means a corruption in `rhh_domain_rollup.tsv` would not be caught by an automated test on the committed file.
**Evidence:** `grep -E "rhh_ac06" scripts/rhh/test_rhh.py` returns nothing.
**Recommendation:** Non-blocking. Consider adding a 10-line `TestAc06Rollup` mirroring `TestAc01Inventory`'s shape (row count = 8, sum invariant, enum check) in a follow-up. Spec language permits the current state — verification reads "File exists, schema matches" with no explicit named test.

### [INFO] ac-04 model pin format note
**Category:** documentation (non-issue)
**Description:** Spec v1.3 fix asks for sha256 of `model.safetensors`. The shipped file pins `58dcba8ea723…` and the methodology doc references `model.safetensors`. The progress.md instead says "weights sha256". The two refer to the same artefact in a multi-branch model layout; not a conflict.
