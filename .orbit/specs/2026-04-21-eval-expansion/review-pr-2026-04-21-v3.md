### ac-06 — row-hash computation + shared normaliser  ✅

Artefact: `scripts/eval_leakage/__init__.py` + `scripts/compute_row_hashes.py` + `eval/row_hashes.tsv`.

- Shared module exports `normalise_header`, `normalise_value`,
  `row_hash`, and a pinned `NORMALISER_VERSION = "1.0.0"`.
- Spec: `lower(strip(header))`, `strip(value)` with NFC + CRLF→LF.
- `eval/row_hashes.tsv` has 237,863 lines (header + comments + data),
  schema `dataset\tcolumn_name\tnormalised_header\trow_hash`, sorted
  for byte-deterministic regeneration.
- File header records `# normaliser_version: 1.0.0` and references
  MADR 0056.
- I did not regenerate to byte-compare (compute_row_hashes scans the
  full corpus; a one-shot re-run is bounded by I/O and out of scope
  for a review). Spec verification requires regeneration produce
  byte-identical output; the determinism guarantees in the script
  (sorted set + fixed-format writer) are sound but the regen itself
  was not performed here.

**Planted-collision unit test:** `scripts/eval_leakage/test_normaliser.py`
exists (8 collide pairs + 6 distinction pairs + version pin + determinism
check). I ran it: **14/14 pass, exit 0.** Includes blind-spot
distinctions (header synonym, internal whitespace, format drift),
which doubles as live documentation of MADR 0056's "Known blind
spots" section.

### Suggestions (not blocking)

- **S-1.** When the augment worklist is finally worked, the ac-04
  HEAD-check verification path will execute for the first time. Worth
  smoke-testing the `pass_floors` re-check against a sample external
  source ahead of that work to surface any prescreen↔manifest schema
  drift early.
- **S-2.** `eval/prescreen_results.tsv` is stale relative to the
  current 448-row manifest (F-M3). Cheap to regenerate; would close
  a small audit-trail gap before the augment cycle.
- **S-3.** `delta_by_coverage.md` is generated but lives outside
  `report.md` — a casual reader of the headline 297/352 misses the
  `previously_covered: 74.0%` vs `newly_covered: 52.7%` split unless
  they scroll to line 527. Inlining the per-row tagged table or at
  least the headline split into the misclassification section would
  improve discoverability.
- **S-4.** The pipeline-level filter test (`test_filter_pipeline.py`)
  mirrors the real `filter_eval_leakage` loop rather than calling it
  directly. Direct invocation would catch a future regression where
  the real function diverges from the test's mock. Low-priority.
- **S-5.** `MADR 0057` references the coverage script transitively
  through the spec. A direct path link in the MADR's
  "Implementation point" section (mirroring how MADR 0056 names
  `prepare_multibranch_data.py`) would tighten the back-link.
