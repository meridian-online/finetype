## The headline, in plain terms

The team asked: when last month's value-only CharCNN drove false-latitude calls
to zero, was that a real architecture win or an artefact of clean synthetic
training data? They rebuilt it on cleaned *real* data, ran a dirty (un-cleaned)
control on the same recipe, and scored both against the shipped v19. The answer:
latitude=0 reproduces, but the un-cleaned control reaches the same zero with
*higher* agreement to v19, and both models agree with v19 on under half of all
columns. The model suppresses false latitude by barely predicting latitude at
all — suppression by starvation, not by discrimination. The cleaning machinery
this whole spec exists to build bought nothing. NO-GO on the late-fusion spec.

That is the confound control doing exactly the job it was added to do. Without
the dirty cell, a naive read would have logged this as "clean data won."

## Firewall integrity — sound and actually applied

The leakage firewall is the non-negotiable (ac-08, spec halt condition), and it
checks out end to end:

- **One shared hasher.** ac-04, ac-06, and ac-08 all import `row_hash` from
  `scripts/eval_leakage/__init__.py` and load `eval/row_hashes.tsv` indexing the
  same field (`parts[3]`, confirmed against the writer header
  `dataset \t column_name \t normalised_header \t row_hash` in
  `compute_row_hashes.py`). `row_hash` normalises both header (lower+strip) and
  value (NFC, CRLF→LF, strip) consistently, so there is no normalisation skew
  between the firewall set and the kept rows.
- **Applied to the kept rows, by construction.** ac-04 Pass C
  (`ac04_triad.py:243-264`) tests `row_hash(header, value)` for every KEEP row
  and flips it to DROP on a hit before it is ever written to the NDJSON or the
  provenance parquet. 202,099 value-granularity collisions were removed this way
  across the 25.6M corpus.
- **Independent audit confirms zero residual.** `ac08_leakage_report.json`:
  17,967,246 kept rows, **0 row_hash collisions, 0 off-partition**, all on the
  measure side (`partition_counts {"1": 17967246}`). The SHA%2 partition leg is
  audited at the source rather than re-applied in ac-04 — correct, because the
  `corpus_pass` parquet is already partitioned to the measure side and ac-08
  proves no kept file leaked onto the calibrate side.
- **The control held to the same standard.** `ac06_build_dirty.py` applies the
  identical `row_hash` firewall to the dirty blend (lines 69-71). Without this a
  clean-cell win could have been an artefact of the dirty cell memorising
  holdout values — closing that hole is what makes the relative comparison fair.

One honest caveat, which the notes already disclose: ac-08 audits the *already
firewalled* `kept_rows.parquet`, so it is a leak-free-**by-construction** check
rather than an independent re-derivation that could have voided the run. That is
a fair design (the firewall moved upstream into the triad after an earlier
kept-level void), and the notes record it plainly. Not a defect; worth naming so
the "0 collisions" number is read for what it is.

## ac-07 conclusion — fairly supported, honestly bounded

The agreement-with-v19 proxy stands in for the win condition's part (b)
net-regression check because the value-level CharCNNs are not wired into the
gated cell-2 pipeline. Assessment: it is a fair stand-in, and the verdict is
neither over- nor under-claimed.

- The proxy isolates broad regression from the intended disease suppression:
  `disagree_other` (ac07_headtohead.py:110-111) counts label disagreements where
  the candidate's call is *not* utc/latitude, so a pure disease-suppression win
  is distinguishable from a broad one. Clean cell: 1,160 of 1,870 columns differ
  on non-disease types — broad, not a confined column-context band. That is what
  fails bars 1 and 2.
- The memo (lines 70-76) states the proxy's limits without sanding them: v19 is
  not ground truth, the value-level model is being applied to a column task it
  was not built for, so the absolute 38% understates true quality. The
  load-bearing claim is *relative* — clean (38%) < dirty (49%), same instrument,
  same reference, same files — and that comparison cancels v19's own bias. The
  NO-GO does not rest on the absolute number; it rests on (a) the dirty control
  matching the clean cell on the disease and (b) cleaning losing to not-cleaning
  on agreement. Honest.
- The result genuinely sits off the pre-committed decision tree (the bars
  imagined "latitude returns"; the actual failure is "latitude stays at 0 but by
  starvation"), and the memo says so plainly (lines 43-58) rather than forcing
  the result onto a bar it doesn't fit. That is the right way to handle a
  pre-registered bar that reality outflanked.

## Stratified cap — preserves the confound control

`cap_ndjson.py` applies per-class reservoir sampling (Algorithm R), ceiling
10k/class, seed 42, **identically** to both blends. Determinism holds (single
`random.Random(seed)`, fixed iteration order). The only clean-vs-dirty
difference that survives the cap is the triad cleaning itself, which is the
whole point of the control. The dirty blend legitimately carries more classes
(194 vs 159) because it keeps off-distribution rows under raw weak labels — the
intended messier label space, not a cap artefact. Validity preserved.

## Latitude starvation — defensible and disclosed

The agent chose NOT to trigger ac-06's refuse-and-relax-floor halt despite only
10 distinct latitude values surviving (below the 50-distinct floor). The
reasoning, recorded in the ac-06 note and carried into the memo: starvation here
is *structural* (quarantine-first keeps latitude-looking values under their
columns' non-latitude weak labels), not confidence-floor-bound, so relaxing the
floor admits noise without manufacturing latitude positives — the identical
futility ac-03 already documented for utc. This is defensible: the halt remedy
exists to fix a too-strict gate, and the gate is not the cause here. Critically,
the caveat is not buried — it is flagged at ac-03, restated at ac-06, and made
the *centre* of the memo's verdict ("suppression by starvation, not by
discrimination", lines 28-40). The experiment does not claim a latitude win it
knows is trivial; it diagnoses the triviality. That is the honest move.

## Code quality (scripts/value_ydf/)

Solid. Memory-bounded streaming throughout (the 25.6M-row corpus never fully
resident — `iter_batches`/row-group passes in ac-02, ac-04, ac-06), factorised
int codes in the triad's Pass A, reservoir sampling in the cap. Shared contract
centralised in `common.py` so the 277-dim feature order cannot drift between the
synthetic-prior and gittables-scoring paths, backed by the ac-00 golden test
(`value_features.rs:77`), which I ran green (2 passed). `__pycache__` is
gitignored, not tracked. No `ac05` script — correctly skipped per the spec's
explicit permission and recorded in the notes.

Minor observations, none blocking:

- **The triad's `+1` makes it a 1-of-2 OR gate in practice.** In
  `ac04_triad.py:229`, `votes = passes_weak + ydf_agrees + 1` — the `+1` is
  signal (c) "L == weak label", which is *always* true for a kept row. So
  `votes >= 2` reduces to `passes_weak OR ydf_agrees`. This is spec-conformant
  (the spec lists (c) as one of the three and (c) is trivially true for the
  column's own label, exactly as the docstring states at lines 13-14), but the
  effective gate is more permissive than "triad" connotes: a value is kept on a
  single real corroborating signal. Worth a one-line note in any follow-on that
  the corroboration is 1-of-2-real, not 2-of-2-real — it bears on how much the
  0.85 floor actually purifies.
- **ac-07 reads stdout-only from the profile subprocess** (`ac07_headtohead.py:46-52`)
  with `stderr` discarded; a silently failing `profile` call would yield an empty
  prediction dict and inflate disagreement. The 1,871-column count and non-zero
  footprints show it ran, so this didn't bite, but a `check=`/returncode guard
  would harden the head-to-head against a quiet model-load failure.
- `ac07_headtohead.py:100-101` counts `ncols` by iterating `preds["v19"]` with a
  bare `+= 1` per key — functional but a `len()` would read cleaner.

rows, the confound control is matched and validity-preserving, and the NO-GO is
